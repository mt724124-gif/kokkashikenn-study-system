# 学習者モデル｜ログから再構成する派生状態

モデルの再訓練ではない。学習マスターを変更せず、実ログから次の出題判断に必要な状態を組み立てる。AIの推定には根拠イベントID・発言・反証・不確実性を付ける。

## 知識IDと情報の分離
知識IDは `区画ID/安定したslug`。例：BIO-0001/phospholipid、bilayer、glycan、protein、mosaic、biomolecule_classes。新しい区画では今回必要な知識だけ作る。全区画の概念マスターを先に増設しない。同義語を統合する場合は旧知識IDのaliasを補足イベントへ記録する。

| 層 | 保存・再構成する情報 |
|---|---|
| 観測事実 | 問題ID/版、問題の完全snapshot、実回答、正誤、自由回答原文、追加質問と説明要旨、本人の復習必要性、日時 |
| 解説後 | 理解した旨の本人申告、残る疑問。初回の理解不足を消さない |
| 推定 | 知識の深さ（用語認識/仕組み理解/応用）、弱点候補、前提知識の不足、評価確実性、根拠イベント |
| 定着 | 別問題・理由確認・経過日数。自己申告や同じ問題の暗記では確定しない |
| 出題履歴 | 問題ID、同じ論点・解法・誤選択肢の反復回数、最終日時 |

状態は未学習・未評価・理解不足・学習中・定着確認待ち・定着確認済み。正答＋理由不明は理解不足候補。誤答＋一部正しい推論は観測正誤0を保ったまま部分理解を推定欄へ残す。解説後の申告は定着確認待ち。7日以上空いた別問題の正答と理由確認を初期の定着条件とする。この条件は暫定ルールであり測定済み能力ではない。

## 既存ログの取り込み
- start.questionsのsnapshotを優先。submitを採点しcheckpointの自由回答等を結合する。同一session/questionを二重計上しない。
- `review_need` / `review_necessity` は旧ログの同義キーとして読む。両方に異値があれば競合として保留。旧self_understandingやassessmentを読み替えない。
- checkpointだけでも実回答と所見を参照する。startがなければ「元snapshot不在」。登録問題への照合は版が一意の場合だけ推定として行う。代替内容が不明なら不明を残す。
- BIOの元Q-BIO-0001-5は未回答。-ALT01は暫定正答を別枠で扱う。CHE/PHA1も同様。古い履歴を新形式に書き換えない。
- question_reportの対象版を採点と弱点推定から除外し、問題不備自体を学習者の弱点にしない。再評価は既存記録の削除でなく補足イベントで行う。
- 分割前の旧ID履歴は関連情報として表示し、子区画の正答率へ複製しない。マスターinitialも保持する。

補助：`scripts/adaptive_learning.py`は抽出・ハッシュ検証・限定ルールの推定用。自由文の意味全般を理解する実装ではない。ChatGPTはその出力だけで判断せず実発言を読み、解釈と根拠をv2イベントに残す。補助スクリプトが実行できない通常チャットでは本手順を直接実行する。
