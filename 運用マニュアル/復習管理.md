# 復習管理

データを二重管理しない。学習マスターの初期履歴＋演習ログのイベントから算出し、復習予定JSON/Markdownは派生ビューとして扱う。ビューが古い場合はログを優先。全ログを取得できないときは優先度を暫定と表示する。

## 抽出順
1. 未完了セッションの最新checkpoint（完了・中断状況を照合）。中断分は翌日の確認候補。
2. 次回復習日が日本時間の今日以前の区画。日付が古いもの、評価未確定・弱点のあるものを優先。
3. ユーザー指定区画。
4. 未学習区画。初回は有効試用問題が約5問ある区画を候補にする。

ユーザーの明示的な区画指定は上記順序より優先。1区画を基本とし、日量30問を強制しない。

## 既存Phase 2と同じ暫定評価
全解答があるsubmitをセッションとして集計。question_reportのID・版を除外し、assessmentの最新値を使う。選択式1/0、自由記述自己評価1/0.5/0。未評価は正解にも誤答にも入れない。正答率は評価済み有効問題の得点合計÷評価済み数。ただし未評価が1問でもあれば理解度は未評価、次回は1日後。

| 状態 | 理解度 | 次回復習 |
|---|---|---|
| 未評価あり、評価可能な問題なし | 未評価 | 1日後の確認候補 |
| 評価完了、得点率60%未満 | 1 | 1日後 |
| 評価完了、60%以上80%未満 | 2 | 3日後 |
| 評価完了、80%以上 | 3 | 7日後 |
| 下記の定着条件をすべて満たす | 4 | 21日後 |

定着条件：直近2回がともに有効5問以上・全問coverage=unit・未評価なし・80%以上、学習日が7日以上離れ、直近に苦手論点なし。試用45問はpilotなので4へ上げない。自己申告だけで習得にしない。

基準日は提出日時をAsia/Tokyoへ変換した日。各間隔は暦日。部分学習はsubmitせずcheckpointを翌日確認候補にし、従来ローカルビューへ学習済みとして混入させない。

ID移行台帳とunitのoriginal_ids/replaced_byを辿り、旧区画の履歴は関連履歴として表示する。分割前の正答率・理解度を子区画へ複製しない。新しい子区画の未評価を保持する。
