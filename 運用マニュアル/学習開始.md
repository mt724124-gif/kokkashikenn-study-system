# 学習開始

1. 「勉強開始」「学習再開」を受ける。対象は `mt724124-gif/kokkashikenn-study-system` のみ。
2. GitHubでmainのhead SHAを取得し、そのSHAをrefにREADMEと今回必要なマニュアルを読む。ファイル一覧も取得し、欠落・取得失敗を記録する。検索の抜粋を全文読了とみなさない。
3. 学習マスターのMarkdown、master.jsonの該当区画、ID移行台帳、問題データ、`演習ログ/記録/`の最新一覧・本文を取得。大きいファイルは行範囲・blob取得で全必要範囲を読み（master.json等のfetch_fileがSHA付き空contentを返す場合はfetch_blobで同じSHAを取得し直す）、途中で切れたJSONを空履歴扱いしない。開始時に履歴を全件取得できなければ既知範囲を明示し、履歴に基づく最適化は暫定とする。
4. `復習管理.md`の順序で中断→期限到来→未学習を候補にする。ユーザー指定があれば優先する。科目・区画を選ぶ質問は実在ID付きの2〜4候補＋自由入力欄。希望がなければ試用5問のある代表区画を1つ提案し、不要な確認を重ねない。
5. 必要なPDFがこの会話で実際に開けるか確かめ、区画の`pdf_file`と`pdf_pages`から該当範囲だけ読む。印刷ページは原本で確認できた場合のみ表示。青問は該当する見出し・問題を検索してページを確定し、青本のページを青問へ流用しない。
6. PDFがなければ「必要巻を添付／既存の照合済み試用問題で暫定実施／今回は別区画」＋自由入力の選択肢を示す。添付パスは環境固有で、別チャットへ持ち越せると仮定しない。青問物理は今回の添付一覧にない。
7. セッションID(UUID)、開始時head SHA、区画ID、採用問題ID・版・根拠・検証状態を確定し、`問題演習.md`へ。起動だけで架空の解答を記録しない。

取得手段の例：GitHubのfetch_file（refに取得SHA）とfetchによるbranch/tree。操作名は環境で再確認する。書込みツールが存在しても成功実績は別に確認する。
