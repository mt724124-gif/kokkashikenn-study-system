# 学習記録｜追記専用・旧外枠互換

正本は `演習ログ/記録/{sequence:08d}-{UUID}.md`。既存ログ・学習マスターは上書きしない。各ファイルにJSONブロックを1つ置く。

## 外枠
`id(UUID), at(ISO8601 +09:00), sequence(正整数), type, request_id(英数字/ハイフン/下線1〜100文字), payload_sha256, payload`

ハッシュは旧仕様と同じ `hashlib.sha256(json.dumps([type,payload],ensure_ascii=False,sort_keys=True).encode()).hexdigest()`。JSON既定の空白も一致させる。厳密計算できなければ値を創作せず未保存データをWorkへ渡す。sequenceは最新最大値+1（件数+1ではない）。再送は同じrequest_idと内容を使う。

## v2イベントのpayload
| type | 必須内容・意味 |
|---|---|
| adaptive_question | session_id, unit_id, question（完全snapshot）, plan（出題判断と根拠イベントID）。1問ずつ追加 |
| adaptive_attempt | session_id, unit_id, question（同じsnapshot）, concept_ids, answer, score, free_response, additional_questions, review_need, interpretation, next_review。実際の送信後のみ |
| learner_observation | session_id, unit_id, question_id, version, concept_ids, evidence（実発言・元event ID）, interpretation。追加質問後の理解更新。初回回答を置換しない |
| session_checkpoint | session_id, unit_id, current_question_id, phase, answers, question_refs, additional_questions, unresolved。未回答や中断を保持 |
| session_pause / session_complete | session_id, unit_id, reasonまたはcompletion_text, weak_topics, unresolved, next_review。終了指示の原文・範囲を保持 |
| question_report | question_id, version, reason。対象版を無効化 |
| question_revision | questions, reason。旧形式の訂正・履歴参照用 |
| log_annotation | target_event_id, reason, supplement。旧ログの不足・訂正を追記。原実回答を創作しない |

旧start/submit/assessmentの型と意味は維持。v2イベントを旧engineに集計させない。question snapshotは `id,version,unit_id,concept_ids,type(single/multi),prompt,options,answer(0始まり配列),explanation,option_explanations,origin,mode,estimated_difficulty,selection_reason,sources,validation,correction_history`。元textの選択式代替は独立IDとoriginal_question_id、provisionalの区分を保持。

interpretationは推定専用：knowledge_gap, depth, prerequisite_candidates, post_explanation_understood（本人申告）, reason_verified（解答による確認）, retention_status, certainty, evidence_event_ids。事実の自由回答・正誤と混ぜない。未取得はnull。根拠なしでreason_verifiedをtrueにしない。

出典は資料名/版、locator(PDF頁または国試回次・番号)、file/URL、確認日時、status、支える論点を持つ。未確認資料は別のsource_requests欄。PDF本文の長文転載はせず自作問題・説明要旨のみ保存。

## 保存・競合・再取得
1. 完了/終了/中断などの本人指示で、保存対象と未保存イベントを確定。本番にテスト成績を入れない。既に回答済みの安全条件を重ねて聞かない。
2. main最新head・tree・全ログ一覧を取得。同じrequest_idはハッシュと本文が一致すれば再送しない。異内容なら停止。同じ問題ID/版の異内容も停止。最大sequenceを取得し空ファイル名衝突がないことを確認。
3. ID・版・区画・session参照・snapshot・正答添字・ハッシュ・根拠・送信事実を検証。元snapshotが足りない過去代替は不明を残し補足イベントを検討する。
4. 最新base treeへ新規ファイルだけ追加し、そのheadを親にcommit。expected_sha=head・force=falseでmainを更新。ファイル単位しか使えない場合はcreateのみ行い、既に成功したrequest_idを再送しない。
5. headが変化したら再取得。別ログ追加だけなら重複とsequenceを再計算。内容競合・予期しない既存変更は上書きせず停止。既存ログ・マスター・ビューを無断更新しない。
6. 保存Commitをrefに各本文を再取得しUTF-8全文・JSON・ハッシュ・件数・ID参照を照合。mainから到達可能か確認。一部失敗なら部分保存と示す。
7. 書込不可・失敗は未保存イベントと同じrequest_idを渡す。保存済みと報告しない。別チャットに引継ぐ際は保存済みCommitと未保存を分ける。

## 旧ログ互換と補足
BIO/PHA1は登録4問と暫定代替1問を区別。CHEはcheckpointのみでstartがない。原Q-*-5 textは未回答。旧復習キー名は読み取り時に統一し、元の外枠や内容を変更しない。実ログから復元不能な代替問題の内容・正答・根拠を推測して埋めない。

補助スクリプトのappend_for_testは隔離TEST_ONLYディレクトリ専用。本番GitHub保存を実装したものではない。本番は上記コネクタ手順を使用する。
