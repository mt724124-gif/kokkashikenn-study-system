# 青本 学習システム：最初に読む

## 起動して学習する

1. 納品ZIPをPCの書き込み可能なフォルダへ**展開**する。ZIP内から直接起動しない。
2. Python 3.10以降が必要。追加のPythonパッケージ、APIキー、外部サービスは不要。
3. Windowsでは `起動.bat` を開く。ブラウザが開かないときは表示された `http://127.0.0.1:8765` を開く。終了は起動した端末でCtrl+C。
4. 科目・学習区画を選び「演習を始める」。選択式4問と自由記述1問に答える。
5. 「回答を保存して採点」。解答・解説・根拠を読む。自由記述は基準を見て自己評価し「追記保存」。
6. 「復習予定」で次回日付と苦手論点を確認する。翌日も**同じ展開先**から起動する。

ターミナルからの起動：

```bash
python app/server.py
```

Pythonのコマンドが `py` または `python3` の環境では、その名前に置き換える。Mac/Linuxは `sh start.sh` でも起動できる。

ブラウザを使わない場合：

```bash
python app/cli.py
```

区画を指定して開始する例：

```bash
python app/cli.py --unit CHE-0004
```

同じ保存先への複数アプリの同時起動は拒否する。まず先に起動したアプリを終了する。初期同梱の学習記録は0件で、テスト用の解答・成績は含まない。

## 現在使える範囲

学習範囲は9科目・1,344区画。問題は代表9区画・45問を同梱した。全区画に問題があるわけではない。「問題のある区画だけ」のチェックを外すと全区画を選べる。問題のない区画は作問依頼文とJSON追加機能を使う。

同梱問題は独自作成の試用問題。根拠は第14版青本の既存本文抽出に照合したが、全図表の目視・専門家校閲・国試相当の難度検証は未実施。coverage:pilotで代表論点のみを評価する。特に炎症の問題は導入部分の確認であり、同区画の治療薬全体を網羅しない。表示の理解度1〜3も試用範囲に限る暫定値で、理解度4には上げない。

## 記録と復習

- 演習開始、解答、自由記述の自己評価、問題報告、問題訂正をそれぞれ**新しいMarkdownファイル**として追記する。
- `演習ログ/記録/` が記録の正本。Markdown中のJSONブロックを機械的に読む。既存ログは手で書き換えず、自己評価や問題訂正を追記する。
- 選択式は正答と完全一致で採点。複数選択は過不足があると0。自由記述は自動判定せず、自分で基準に照らして0 / 0.5 / 1を付ける。採点者はself_rubricとして記録する。
- 最新セッションの評価率から暫定理解度を算出：60%未満は1、60%以上80%未満は2、80%以上は3。自由記述未評価なら理解度は未評価のまま。
- 復習間隔：未評価・理解度1は翌日、2は3日後、3は7日後。理解度4は区画全体を扱う5問以上のセットで、7日以上空けた連続2回の80%以上・弱点なしを満たしたときのみ。間隔は初期運用ルールであり、学習効果の医学的保証ではない。
- セッション中の無効問題は点数・分母・問題数から除外する。全問無効なら学習済みとして数えない。以前の有効なセッションは残る。
- `復習管理/復習予定.md` と `学習ダッシュボード/進捗.md` は再生成ビュー。初期状態を保持する学習マスターだけで最新進捗を判断しない。
- 日付はAsia/Tokyo相当のUTC+9。PC時計を使用する。

「学習網羅率」は一度以上有効な演習をした区画数÷1,344。「習得率」は理解度4の区画数÷1,344。要確認フラグ346件は学習状態と別である。印刷ページ不明は補完していない。

## 問題を追加・訂正する

1. 全区画から対象を選ぶ。
2. 「問題を追加・訂正」→「選択区画の作問依頼文をコピー」。ChatGPTに貼り付ける。
3. 青本を参照させ、得られた問題の根拠・正答・説明を確認する。原本を確認できない問題はvalidation.statusをdraftにする。
4. JSON配列を追加フォームに貼り付け、理由を書いて保存する。見本は `問題データ/questions.json`。
5. 新規問題は重複しないID・version:1。訂正は同一ID・同一区画でversionを1増やす。**過去の解答は当時の問題版・正答・解説を保存する。**

検証状態はdraft / text_checked / human_checked。draftは出題しない。text_checkedは文字層照合、human_checkedは人による確認を意味するが、システム自身がその申告の真偽を自動検証するものではない。coverage:unitは区画全体の代表性を人が確認した後に限って指定する。今回の試用問題はpilotのままにする。

誤りを見つけたら「問題を報告・無効化」。分類＋自由記述で報告し、その版を出題・成績集計から除外する。元解答と報告は消さない。修正問題は次の版として追加する。新しい版は利用でき、旧版の無効化は保持される。

## データの区別

| 保存先 | 役割 |
|---|---|
| 学習マスター/青本_学習マスター_v1.2.md | 学習範囲の正式版候補・初期状態 |
| 学習マスター/master.json | 同時生成した機械用索引・初期記録の全8欄 |
| 学習マスター/ID移行台帳.json | 旧44ID・仮75ID・新75IDの対応 |
| 資料/青本_学習マスター_v1.1.md | 変更前原本の保持用写し |
| 問題データ/questions.json | 初期45問 |
| 演習ログ/記録/*.md | 解答・評価・問題変更の追記記録 |
| 復習管理/復習予定.* | ログから計算した最新予定 |
| 学習ダッシュボード/進捗.md | 科目別の網羅率・習得率 |

範囲Markdown・索引は生成物の組なので片方だけ直接編集しない。不一致は起動時に検出して止める。再生成スクリプトは `python scripts/build_master.py`。これは資料にある入力から再現生成するため、独自に編集した内容を引き継ぐ用途には使わない。

旧IDは退避参照として維持し、区画履歴から旧初期値・旧演習を見られる。旧理解度や回数を新区画へ複製しない。新75区画の初期理解度は未評価。今後の旧外部ログの一括取込は未実装。

## ChatGPTとの関係・バックアップ

ChatGPT内では出題・解答説明・作問JSONの作成・提出されたログの分析を支援できる。このローカルアプリの常時起動、PC上のログの自動読込・保存、GitHub同期はChatGPT会話画面だけでは行わない。自動AI作問や自由記述のAI採点には別途API連携が必要だが、現版には導入していない。

毎日30問なら6区画を選んで5問ずつ解く手動運用ができる。新規4区画＋復習2区画を目安にし、必要に応じて減らす。問題が不足したら追加する。科目をまたぐ自動の日次割当は未実装。

バックアップはアプリを終了して**展開先フォルダ全体をコピー**する。Obsidianではこのフォルダを開くか既存VaultへコピーしてMarkdownを参照できるが、自動同期はしない。別PCへ移すときも記録フォルダごと移す。途中の解答はブラウザ内に保存するため、ブラウザ変更では引き継がれない。提出済みの解答はMarkdownに残る。ログを外から追記した場合はサーバーを再起動して読み込む。

GitHubへの反映は別途の明示承認後。既存READMEの上書き、他リポジトリの操作、PDFの登録は行っていない。

## 再実行できる検証

```bash
python -m unittest discover -s tests -v
```

テストは一時フォルダを使い、実際の学習ログにテスト成績を混入させない。Windows固有の起動・ファイルロックや、ブラウザでの見た目・クリック・クリップボードは実機確認が必要。
